1. Executive Summary
IL Quantum Portal is a browser-based, single-page analytics portal for claim data exploration. The application allows business users to move from a branded homepage into a dashboard, select or retain dashboard modules, upload Excel or CSV claim files, monitor parsing status, filter data through slicers, view claim analytics tables/charts, export outputs, and manage display settings.
The IT team must develop a functionally equivalent web page that preserves the working behavior of the latest baseline. The implementation must prioritize stability of the homepage door animation, browser responsiveness during file parsing, predictable slicer behavior, and module-wise data isolation.
Critical Success Definition
The portal is successful when a business user can open the homepage, trigger the door animation, enter the dashboard, upload claim files, filter data, refresh output, clear filters, view file parsing details, export outputs, and use settings without page crash, UI freeze, or layout breakage.

2. Business Objectives
•	Provide a unified browser-based portal for claim data ingestion and analysis without requiring backend deployment for the baseline version.
•	Allow business users to upload multiple Excel or CSV files and generate dashboard summaries using normalized data.
•	Provide clear slicers for policy, ILTC, network hospital, relation, claim type, status, age band, disease category, IPD/OPD and MonthYear.
•	Enable fast operational analysis through tables, charts, export options, uploaded file progress panel and custom chart builder.
•	Keep the user experience polished with controlled animations, stable popups, responsive rendering and clean ICICI Lombard theme alignment.

5. Current Working Baseline Summary
The current baseline version is IL_Quantum_Portal -IL theme V30_6. This version is considered stable for homepage door animation, dashboard load, slicer behavior, file panel behavior, export popup default-hidden behavior, and file parsing popup delay. IT team must use this baseline as the behavioral reference.
•	Homepage door animation must remain isolated from dashboard and parsing logic.
•	Dashboard top ribbon must include logo, brand, compact Home icon with back/forward, Menu icon, Excel upload icon and user profile icon.
•	User profile dropdown must open above dashboard cards and include name, settings icon and logout option.
•	Slicers must open above charts/cards, include search, select all and remove all, and close after selection.
•	Export Options panel must remain hidden by default and must open only when Export icon is clicked.

6. Target Solution Architecture
6.1 Technology Architecture
•	Single-page HTML file containing HTML, CSS and JavaScript blocks.
•	Client-side file parsing using Papa Parse for CSV and SheetJS/XLSX for Excel files.
•	Client-side chart rendering using Chart.js or equivalent library already referenced by the portal.
•	No mandatory backend service for baseline implementation.
•	Data remains in browser memory during the active session.
•	Export operations are handled from browser-side data and rendered chart/table states.
6.2 Logical Architecture
Layer	Responsibilities
Presentation Layer	Homepage, navigation, dashboard shell, top ribbon, slicers, cards, tables, charts, file panel, settings panel, export popup.
Interaction Layer	Door animation, menu dropdown, user dropdown, slicer popup, refresh, clear, view toggle, export selection, file panel opening.
Data Processing Layer	File validation, queue management, CSV/Excel parsing, row normalization, field mapping, module state management.
Analytics Layer	Filtered data computation, section summaries, chart datasets, custom chart builder, table rendering, insight text rendering.
State Layer	Uploaded files, file queue, active module, module-specific data, filters, chart instances, section view states, settings.
Utility Layer	Toast messaging, formatting, currency and number conversion, date/month extraction, export helpers, settings/theme utilities.

7. Page and Layout Requirements
7.1 Homepage
The homepage is the first visible state. It must display the portal branding and a door-opening animation trigger. The door animation must complete before the next page is shown. Failure in unrelated dashboard JavaScript must not be allowed to break the homepage animation.
•	Placement: full browser viewport.
•	Interaction: click or invoke homepage entry action to animate door-open state.
•	Transition: after animation duration, hide homepage and show navigation/dashboard flow.
•	Do not place dashboard initialization logic inside the homepage animation function.
•	Do not introduce heavy processing before homepage transition completes.
7.2 Navigation / Business User Entry
•	Navigation page appears after the homepage door animation.
•	Business Team button opens dashboard.
•	Back to homepage action resets internal login state.
•	Navigation should not render dashboard charts until dashboard is explicitly opened.
7.3 Dashboard Top Ribbon
The dashboard top ribbon is sticky at the top and uses an ICICI Lombard orange/red gradient. It contains the logo, brand label, Home control, Menu icon, Excel upload icon and user profile icon.
Element	Placement	Behavior
Logo	Top-left inside dashboard ribbon, fixed/contained within ribbon height.	Static branding element; no click action.
Brand	Immediately right of logo with white text.	Shows ICICI Lombard and IL Quantum. No click action.
Home Control	After brand. Compact icon-only control with left/right arrows.	Left arrow calls previous-page action, home icon calls homepage action, right arrow calls next-page action.
Menu Icon	After Home control. Icon-only hamburger.	Hover opens menu list. Dropdown must remain stable when moving cursor from icon to list.
Excel Upload	After Menu icon.	Opens hidden file input for CSV/XLS/XLSX.
User Icon	Far right of ribbon.	Hover opens user profile dropdown above all charts/cards.

7.4 Dashboard Body Before Upload
•	Before upload, dashboard body shows centered anniversary/portal logo on orange landing area.
•	Custom chart builder and filters remain hidden until data exists.
•	Module navigator strip remains visible and indicates selected module or default dashboard.
•	Menu and Excel remain available.
7.5 Dashboard Body After Upload
•	Slicer row appears above dashboard chart/cards.
•	Tiny action icons appear beside slicers: Refresh, View, Export, Clear, Uploaded Files.
•	Dashboard sections render as cards containing table/chart area and section-specific controls.
•	Custom chart builder appears after data upload.

10. File Upload and Parsing Requirements
10.1 Upload Rules
•	Accepted extensions: .csv, .xlsx, .xls.
•	Maximum file count and file size must follow portal configuration constants.
•	Duplicate file names must be skipped within selected module state.
•	Valid files are added immediately to uploadedFiles and fileQueue.
•	File panel should open/reflect status during parsing and close immediately after all successful files finish as per V30_6 behavior.
10.2 Parsing Flow
71.	Receive browser File object from hidden file input.
72.	Create file metadata with id, name, type, size, rawSize, status, monthYear, rowCount and progress.
73.	Add metadata to uploadedFiles and add file to fileQueue.
74.	Process fileQueue sequentially.
75.	For CSV, use Papa Parse if available, else fallback parser.
76.	For Excel, use XLSX to read workbook, iterate sheet names and convert each sheet to JSON rows.
77.	Normalize row headers and add file metadata fields such as file id, file name, sheet name and MonthYear.
78.	Append normalized rows to combinedData.
79.	Update file status to Uploaded/Empty/Error.
80.	After queue completes, render filters and dashboard, save module state, close file panel immediately on successful run.
Performance Requirement
Do not rebuild the file panel DOM on every FileReader progress event. Throttle panel updates and defer heavy dashboard rendering until after browser paint where possible.

15. Settings and Theme Requirements
•	Settings modal is opened from User Profile dropdown settings icon.
•	Settings should control theme preset, color scheme, dark mode, font size and other existing configuration items.

16. Non-Functional Requirements
Area	Requirement
Performance	Parser and dashboard rendering must avoid long main-thread blocking. Use throttled progress updates and scheduled renders.
Responsiveness	Layout must work on desktop and have responsive fallback for smaller screens.
Reliability	A syntax error in dashboard logic must not be introduced; every JS change must be validated to protect homepage animation.
Usability	Dropdowns must remain stable, popups must not open by default, and slicers must close after selection.
Maintainability	Code must remain in numbered block format. Future changes must be done by block replacement.
Accessibility	Controls must have titles/tooltips where possible and readable font/color contrast.
Security	Client-side files must remain in browser memory. Production version should add authentication, authorization and dependency review.

17. Security and Governance
•	Production implementation should evaluate SSO or enterprise authentication for non-local deployment.
•	Role-based access should be implemented server-side in future enterprise deployment.
•	Uploaded data should not leave browser unless a backend integration is explicitly introduced.
•	External library versions must be pinned and scanned before production release.
•	No hard-coded sensitive credentials must exist in the HTML file.
•	If production hosting is required, apply HTTPS, CSP, dependency integrity checks and file size constraints.
18. Error Handling and Notifications
•	Use toast for success, warning and error messages.
•	Invalid file type, duplicate file, too-large file, empty file and parsing error must show user-friendly messages.
•	Export failure should show error toast and preserve dashboard state.
•	If required columns are missing for a section, show message inside that section rather than crashing.
•	If file parsing fails, continue processing remaining queued files when possible.

Appendix B - End-to-End Journey Flows
Journey 1 - First entry to dashboard
1. User opens the portal HTML file.
2. Homepage landing appears with door visual only.
3. User clicks homepage entry area.
4. internalLogin() marks internalLoggedIn true and adds door-open class.
5. After animation delay, homepage hides and navigation page displays.
6. User clicks Business Team.
7. openInternalEmp() opens dashboard page and calls resetDashboardToModuleLanding().
8. Dashboard shows top ribbon, module title strip, and pre-upload centered image.
Journey 2 - Select module before upload
1. User hovers Menu icon.
2. Menu dropdown opens and remains stable because hover bridge covers icon-to-list gap.
3. User hovers category such as Health Claim.
4. Submenu opens to the right.
5. User clicks GHI Summary or another submenu item.
6. openDashboardModule(moduleName) saves previous module state and restores selected module state.
7. Title strip updates to selected module.
8. If selected module has no data, centered landing image remains visible.
Journey 3 - Upload and parse files
1. User clicks Excel icon in ribbon.
2. Hidden file input opens.
3. User selects CSV/XLSX/XLS files.
4. handleFileUpload validates format, size, duplicate names, and count.
5. Valid files are added to uploadedFiles and fileQueue.
6. File panel opens compactly and shows queued/processing status.
7. processFiles reads each file sequentially.
8. parseCSV or parseExcel parses rows.
9. normalizeRows standardizes columns and adds metadata.
10. appendData adds rows to combinedData and uniqueColumns.
11. runStableProcessingProgress completes progress and continues queue.
12. After queue ends, dashboard renders filters and sections.
Journey 4 - Filter dashboard with slicers
1. After data upload, slicer row appears.
2. User clicks a slicer pill.
3. Dropdown opens above charts/cards.
4. User can search values inside dropdown.
5. User checks a value, clicks Select All, or clicks Remove All.
6. globalFilters is updated.
7. Dropdown closes after selection.
8. Dashboard table/chart values rerender based on getFilteredData().
Journey 5 - Refresh and clear filters
1. User clicks Refresh icon beside slicers.
2. Dashboard rerender is scheduled to avoid immediate UI lock.
3. User clicks Clear All icon.
4. globalFilters is reset to empty object.
5. Visible slicer checkboxes are unchecked.
6. Dashboard rerender is scheduled.
7. Tables/charts return to unfiltered values.
Journey 6 - Export dashboard data
1. User clicks Export icon beside slicers.
2. Export Options popup opens only on click and overlays charts.
3. User chooses CSV/PPT/PDF and graph/table/raw option.
4. handleExportOption triggers correct export behavior.
5. Outside click closes export popup through existing popup closer logic.
Journey 7 - View uploaded file details
1. User clicks tiny Uploaded Files icon beside slicers.
2. toggleFilePanel() opens the existing uploaded file panel.
3. Panel lists uploaded/queued/error files with status and progress.
4. User can review parsing status and close/collapse using existing panel behavior.
Journey 8 - User profile settings/logout
1. User hovers the top-right user icon.
2. Compact user dropdown appears above charts/icons.
3. User clicks tiny Settings icon beside user name.
4. Existing Settings modal opens.
5. User clicks Logout.
6. goToHome() returns portal to homepage.
Journey 9 - Switch modules after upload
1. User opens Menu while dashboard has data.
2. User selects another module.
3. Current module upload/data/filter/chart state is saved.
4. New module state is restored.
5. If new module has uploaded data, filters and cards render.
6. If no data exists, landing image appears.
